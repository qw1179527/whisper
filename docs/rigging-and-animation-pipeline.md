## 三、骨架（20 根）

`Root → Hips → Spine → Chest → Neck → Head`，四肢各
`Shoulder/UpperArm/LowerArm/Hand` 与 `Thigh/Shin/Foot`。

## 四、蒙皮策略（**如实说明取舍**）

这些部件是**分离的刚性件**（各肢体一个网格），不是连续蒙皮网格。所以：
- 部件主体 → 绑到该肢体骨（权重 1）
- **邻近关节的一小段 → 沿轴参数 t 在两骨间线性过渡**（`BLEND = 0.22`），避免关节撕裂
- 躯干跨髋/脊/胸三骨，按 Z 分三段加权

**这不是次表面级别的连续蒙皮。** 真实人形需要先重拓扑成整体网格再刷权重 —— 属后续里程碑。
（看图可见：髋部仍有折角、手臂是独立柱体、头相对偏小 —— 属**低模人形**，不是"真人级"。）

## 五、行走动画（16 帧 @24fps ≈ 0.67s 一周期）

口径：大腿前后摆 ±26°、手臂反摆 ±18°、髋部起伏 2.2%H、躯干前倾 4°、胸随步态侧转 ±3°。
相位用整周期正弦 ⇒ **循环无缝**；小腿只在向后摆时弯曲（膝盖不会向前反折）。

## 六、抓到的两个真缺陷（**都是"数据完整但没生效"**）

### 缺陷 1：关键帧只打在"有变化的骨骼"上 ⇒ 轨道塌成 2 帧
第一版只在"该骨骼有变化"的帧打键。导出后实测：
```
Hips 的 location 轨道 17 个采样 ✓  而 rotation 轨道只有 2 个 ✗
```
⇒ 整段动画塌成"首尾两帧插值"，看起来像静止 —— 而**导出不报任何错**
（glTF 如实写出"你给的关键帧"）。
**修**：每个关键帧上把所有参与骨骼都写一遍（哪怕数值没变）。
**但要注意**：glTF 会正确地**折叠恒定值轨道**（我实测 52 条轨道是 2 采样、
而真正在动的 8 条是 17 采样）—— 那不是 bug，是优化。

### 缺陷 2：验证时选错了帧 ⇒ 得出"完全没动"的错误结论
第一版我对比 frame 1 与 frame 9，两张图 **SHA256 完全相同**，于是判定"动画没生效"。
**但 `sin` 在 0 与 π 处都是 0** —— 这两帧**本来就是同一姿态**（步态的两个中间位）。
⇒ 换到极值帧（1/3/5/7/9）后：**5 帧 5 个不同哈希**，姿态明显不同。
**教训：验证要选"应当不同"的样本；拿两个本就该相同的点去比，会得出反向结论。**

### 缺陷 3（同轮抓到，属渲染链）：`[InitializeOnLoadMethod]` 时机早于资产导入
```
[UrpSetup] 编辑器加载时自动配置 URP 失败：InvalidImportException:
  Cannot load. Path Packages/.../Textures/BlueNoise64/L/LDR_LLL1_0.png
  is correct but AssetDatabase cannot load now.
```
⇒ `currentRenderPipeline == null` ⇒ 渲染整屏近黑（mean luma 5.2）。
**修**：在**入口方法里显式配置**（`RenderEvidenceCapture.Run` 加了 `UrpSetup.ConfigureUrp()`）。
`BuildScript` 一直是这么做的，所以出包路径没这个问题 —— 只有取证路径漏了。
**教训：不要依赖"加载时机"这种隐式契约，要在真正需要它的入口处显式保证。**

## 七、复现命令

```bash
# 1) 从 .blend 导出玩家几何
blender -b player-source-v5.blend --python tools/export-player-geo.py -- geo.glb
# 2) 绑骨 + 烘行走动画（输出带 skin 与 animation 的 GLB）
blender -b --factory-startup --python tools/rig_player.py -- geo.glb rigged.glb walk
# 3) 渲染动画帧（**必须看图**；选极值帧）
blender -b --factory-startup --python tools/render_anim_frames.py -- rigged.glb out/ "1,3,5,7,9"
```
