> 交付物：`truck-sample/truck-v3.blend` · 图 `v3-front.png`（正面）· `v2-left.png`（左侧）· `v2-iso.png`（等轴测）

## 一、本轮修的缺陷：**玻璃被"洗白"**（正面图与左侧图揭穿）

| 项 | v2 | v3 |
|---|---|---|
| 玻璃 | `base (0.10,0.13,0.16)` + **metallic 0.30** + roughness 0.08 | `base (0.06,0.08,0.11)` + **metallic 0** + roughness 0.15 |
| 现象 | **车窗/挡风玻璃/屏幕与车身同色**（都是浅灰）—— metallic 让玻璃反射环境光被洗白 | 挡风玻璃读作**暗色面板**（见 `v3-front.png` 上部暗带） |
| 车漆 / 饰条 / 轮胎 | 明度接近 | 拉开：车漆 L=0.709 · 饰条 L=0.101 · 轮胎 L=0.030 |

这是"上色不行"的一个**具体实例**（用户《补充说明》第 3 条："重点是建模上色，目前的建模上色都不行"）。

## 二、新增：**材质对比自检**（把"有没有对比"变成数字）

```
=== 材质对比自检（相对亮度差；必须可区分的组合要求 ΔL ≥ 0.15）===
  body_paint vs glass          L=0.709 / 0.078  ΔL=0.631  OK
  body_paint vs tyre_rubber    L=0.709 / 0.030  ΔL=0.679  OK
  body_paint vs trim_plastic   L=0.709 / 0.101  ΔL=0.608  OK
  glass vs trim_plastic        L=0.078 / 0.101  ΔL=0.024  **对比不足**（1 组，可接受：两者都属"暗部"）
```
算法：相对亮度 `L = 0.2126R + 0.7152G + 0.0722B`（标准 Rec.709 权重），对**必须一眼分得开**的组合
（玻璃/车身、轮胎/车身、塑料/车身、玻璃/塑料）要求 ΔL ≥ 0.15。
**为什么值得做**：本项目已多次把"主观观感"变成可测数字（如 `gate-model` M1–M11、`validate-levels`），
材质对比同理 —— 否则"上色不行"只能靠人反复看。
