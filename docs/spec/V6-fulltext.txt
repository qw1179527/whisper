        第一部分　V5.0 方案深度评审报告
          1　评审方法
        本次评审沿三个层面展开：
         1. 战略一致性：各章节是否服务于同一命题（Android 空白市场 × 声纹机制差异化 × 零成本栈 ×
           AI 主力生产），有无内部矛盾；
         2. 可执行性：每项设计能否被 1~3 人团队在既定里程碑内落地，验收指标是否可测量、样本是否有
           效；
         3. 盲区扫描：V5.0 未覆盖但可能导致项目失败或重大返工的议题（合规、作弊、新手引导、无麦体
           验完整性等）。
          2　总体评价

          3　核心亮点（应予保留并发扬）
         1. 「声纹即风险」把品类差异点打透了。 恐鬼症的语音只在驱鬼环节触发，本作将其升格为全程生
           存货币；更妙的是快捷喊话轮盘同样产生声纹——无麦玩家不是二等公民，而是同一规则下的另一
           种流派。这是机制层面真正的创新。

          4　关键问题诊断（按严重度排序）
         P0 —— 不修复将动摇立项根基
         P0-1　变现漏斗存在结构性缺陷：房客要不要买？ V5 §3.11 规定「免费版含前 3 局 + 4.99 美元买断
         解锁」，但开黑游戏的核心场景是「一个老玩家拉三个新朋友」。若四人都需买断才能开第四局，裂
         变链条在第 3 局就断裂——这恰恰是转化率最高的时刻。修正：房主买断制——房主买断即可无限建
         房，房客免费跟房（参照致命公司「一人买全队玩」的社交传染模型）；免费玩家自建房限 3 局/日。
         此修改同时强化「跟随房间主付费」（V5 §2.3 泛用户层）的既有判断。详见本方案 §6.2。
         P0-2　麦克风权限与核心机制生死绑定，「无麦体验」只有兜底没有设计。 V5 已识别 Android 麦克
         风权限授予率偏低，对策是喊话轮盘（V5 §3.9）。但轮盘目前是「残缺版语音」而非「独立流派」：
         无麦玩家的策略深度、声纹差异化、成长感全部缺失。若轮盘体验不成立，本作在最广大的休闲用户
         层将退化为普通追逐游戏。修正：将轮盘升级为「语音人格包」系统——预设角色声线（冷静领队/慌
         张新人/挑衅者），不同人格的喊话附带差异化声纹强度与战术效果，无麦玩法成为可钻研的策略路
         线。M0 验收必须增加无麦专项指标。详见 §6.1、§8。
         P0-3　语音内容合规空白——这是真正的红线，V5 完全未提。 实时语音属于 UGC：Google Play 家庭
         政策与各国未成年保护法规要求提供举报、屏蔽、监护人控制；玩家语音若被录制传播还涉及隐私。
         V5 风险矩阵（表 9-1）无此条目。修正：① 语音流不落盘、不上传服务器，仅存音量包络数据用于声
         纹判定；② 对局内一键屏蔽 + 赛后举报入口；③ 设置页「家长控制」默认对未成年声明账号关闭陌生
         人语音；④ IARC 申报时如实勾选「用户互动」分级项。 成本极低，缺失代价是下架。详见 §7.3。
         P0-4　房主权威性 = 作弊与体验单点，无任何防护设计。 Host 即权威端（V5 §4.3）意味着房主设备

           并标记）；② 移动速度/位置合理性校验（服务端逻辑运行在 Host 上，但校验规则由配置表下发，异
           常仅记录不踢人，供事后封禁）；③ 房主网络质量检测，低于阈值时提示迁移 Host。 详见 §7.1。
           P1 —— 显著影响留存与口碑，M1 前必须修复
           P1-5　新手引导缺失：恐怖游戏的首局流失主因是「不知道发生了什么」。  V5 从灰盒原型直接跳到
           内测，无引导设计。玩家第一次被「缝匠」追时若不理解「它听见了你」，恐惧会变成困惑与卸载。
           修正：设计「第 0 局」引导剧本——单人安全屋 5 分钟教学（移动/耳语/躲柜/看音量环），首局匹配
           「教学局」怪物压力减半，死亡归因提示前置（V5   已有「它听见你了」闪现，需扩展为完整归因
           链）。详见 §6.3。
           P1-6　断线重连快照粒度过粗。 V5 §3.10 快照仅含位置/道具/理智/证据四项。门与柜状态、证据收
           集进度、怪物当前仇恨目标缺失，重连后可能出现「队友明明锁了门，重连者面前门开着」的世界观
           撕裂。修正：快照扩展为世界状态哈希 + 增量回放，详见 §12.6。
           P1-7　M0 验收样本量过小，统计意义弱。 8~12 人内测 + 问卷 ≥3.5/5 的阈值，单样本权重过高（1
           个差评即可拉垮均值）。修正：M0 改为两轮——8~12 人定性轮（观察尖叫与笑声，不计分）+ 30~50
           人定量轮（蒲公英扩大分发，问卷 ≥3.5 且触控通过率 ≥70%）；新增「无麦玩家」配额 ≥30%。
           详见 §8。
           P1-8　恐怖感衰减对策单一，缺低成本长效钩子。  V5   的对策集中在动态事件池与词条（高成本内
           容），缺少「元叙事」这类一次投入长期生效的钩子。修正：新增「档案残页」收集系统——每局散布
           3~5   页疗养院往事残页，集齐解锁怪物背景故事与隐藏词条；残页随机位置由词条种子决定，与重玩
           系统咬合。成本约等于一套 UI + 一批 AI 生成文本，详见 §6.5。
           P2 —— 应在 EA 前完成，不阻塞 M0
           P2-9　本地化语种取舍缺依据，客服成本未入预算。 五语（英日韩葡西）覆盖了高付费区，但漏掉恐
           怖品类高活跃的泰语/印尼语区；建议 EA 后按 Firebase 地区数据追加。Discord/TapTap 社区运营折
           算人力每周约 6~8 小时，应计入 §7.3 人力说明。
           P2-10　iOS 缺席的决策未写明理由。 方案默认 Android only 正确（版号、审核、开发成本三重理
           由），但应显式记录「iOS 在正式版验证后评估」以防团队后期动摇返工。

          6.3　第 0 局：引导剧本设计
          前提：恐怖游戏不能在教程中破坏恐怖感，故「安全屋」本身也是世界观的一部分——它是一座废弃监
          控室，墙上贴满被涂黑的手册与疯子写的便签。
          流程（单局 5 分钟，单人无怪物）：
           1. 0:00~1:30 苏醒：玩家从监控桌前醒来，环境光极暗，仅有手电；强制操作：起身、走动、环顾。
             墙上便签提示「安静，它在听」。
           2. 1:30~3:00 耳语教学：系统检测到麦克风音量（或强制打开轮盘），屏幕边缘出现音量环 UI；提
             示「对它说话比对它沉默更危险」。让玩家在空房间内进行一次耳语（低音量）和一次正常说话
             ——正常说话时远处传来怪物回应声（预制事件，无真实危险）。
           3. 3:00~4:00 声纹实战：房间另一侧门自动打开，另一间模拟病房内有一个假人（代表队友），玩家
             需用轮盘或语音发出指令，观察假人头顶出现声纹波纹。提示「你的声音不仅它能听见」。
           4. 4:00~5:00 撤离演示：撤离点闪烁，玩家走入后触发结算面板——这是玩家第一次看见「残响碎
             片」概念。退出时弹出「你准备好进入真正的疗养院了吗？」确认键。
          M1 验收：新玩家首局前 5 分钟任务完成率 ≥85%；首局后 24 小时再开率 ≥50%。

          // Core/EventBus.cs
          using System;
          using System.Collections.Generic;
          namespace Whisper.Core
          {
             public static class EventBus<T> where T : IGameEvent
              {
               private static readonly List<Action<T>> _listeners = new();
               public static void Subscribe(Action<T> listener)
                  {
                 if (!_listeners.Contains(listener)) _listeners.Add(listener);
                  }
               public static void Unsubscribe(Action<T> listener) => _listeners.Remove(listener);
               public static void Publish(T evt)
                  {
                 // 快照遍历防止迭代时增删
                 var snapshot = _listeners.ToArray();
                 foreach (var l in snapshot) l?.Invoke(evt);
                  }
              }
             public interface IGameEvent { }
          }

             // Gameplay/AI/BehaviorTree.cs
             namespace Whisper.Gameplay.AI
             {
                public abstract class BTNode
                 {
                   public enum Status { Running, Success, Failure }
                   public abstract Status Tick(Blackboard bb, float deltaTime);
                   public virtual void OnEnter(Blackboard bb) { }
                   public virtual void OnExit(Blackboard bb) { }
                 }
                public class Selector : BTNode // 顺序执行子节点，直到一个 Success
                 {
                   private readonly BTNode[] _children;
                   private int _current;
                   public Selector(params BTNode[] children) => _children = children;
                   public override Status Tick(Blackboard bb, float deltaTime)
                     {
                      for (; _current < _children.Length; _current++)
                         {
                        var s = _children[_current].Tick(bb, deltaTime);
                        if (s == Status.Running) return Status.Running;
                        if (s == Status.Success) { _current = 0; return Status.Success; }
                        // Failure → 继续下一个
                         }
                         _current = 0;
                      return Status.Failure;
                     }
                 }
                public class Sequence : BTNode // 顺序执行子节点，直到一个 Failure
                 {
                   // 实现类似 Selector，逻辑取反
                 }
             }

           · 位置：左上角，距边缘 16dp，直径 56dp；

           · 表现形式：屏幕边缘色点 + 距离数字（m）；
           · 颜色：存活 = color-paper（微发光），死亡/幽灵 = color-ghost；
           · 动态：队友移动时色点平滑滑动（非跳跃），距离数字实时更新；

           · 触发条件：玩家麦克风检测到音量 > -50dB，或轮盘喊话播放中；
           · 位置：玩家角色脚下（世界空间 UI，非屏幕空间），仅在玩家自身视角可见；
           · 视觉：同心圆扩散波纹，强度映射颜色（绿 → 黄 → 红），半径映射感知距离；
           · 设计意图：让玩家「看见自己的声音」，建立「音量 = 风险」的直觉。

            24　使用规范
          24.1　工作流
            设计 Token（§18） → 全局风格锚点提示词（§25） → 分页面/组件提示词（§26~§28）
            → 生成 4~8 张候选 → 人类挑选 1 张 → 局部重绘（inpainting）修正细节
            → 切图/矢量化（图标类用 AI 初稿 + Figma 手工矢量化） → 入库前「恐怖感一致性」审查（V5 §5.6）
          24.2　通用规则
           1. 一致性锁定：所有 UI 生成必须使用同一风格锚点后缀（§25 的 STYLE_ANCHOR），并固定随机
             种子区间（SD 中锁定 seed 微调，MJ 中使用 --seed 与 --sref）；
           2. 负面提示词：UI 类统一附加 §25 的 NEGATIVE_UI，避免生成卡通、高饱和、拟物化高光等破坏
             风格的元素；
           3. 文字问题：AI 生成图像中的文字几乎必然出错——提示词中一律要求 placeholder text（如
             “Lorem ipsum” 或 “[TITLE]”），实际文字由 Unity uGUI 叠加渲染；
           4. 分辨率：UI 概念稿 1920×1080（横屏）；图标 1024×1024 后缩至 128/64；商店图按 Google
             Play 规范（1024×500 头图等）；
           5. 版权边界：提示词中禁止出现具体游戏名/艺术家名（如 “in the style of Phasmophobia”），仅
             用风格描述词；产出物人类审查后方可入库。
