# 程序化人体生成的正确方法（Lead 实测 · 交付 build-render）

> 我为此迭代了 **9 版**（用户三次说"建模真烂"）。这里只写**被渲染图证实的结论**，
> 每条都附"怎么错的"，因为**错法比正法更有指导价值**（我重复踩了 4 次同一类坑）。

## 一、四条路线，只有一条通

| 路线 | 结果 | 失败原因（渲染图证实） |
|---|---|---|
| ① 锥形胶囊拼装 | ✗ | 部件之间必然有接缝/错位；比例无法整体协调 |
| ② Blender **Skin 修改器** | △ | 连续了，但**方块感重、肘部伪影、肩过宽** |
| ③ **Metaball 元球** | ✓（唯一通） | 见下 |
| ④ 手工 bmesh 逐环堆轮廓 | ✗ | 改一处要重调全部数字；部件关系无法保证 |

**结论：用 Metaball。** 它的价值是"元球之间**自动融合成平滑曲面**"——这正是"有机体"的成因。

## 二、元球的**唯一关键判据**（我在这上面错了 4 次）

> **珠间距 / 元素半径 ≤ 1/3 → 表面连续；> 1 → 表面出现"珠链"（一节节肿包）。**

判据是**这个比值**，不是珠数、也不是半径的绝对大小。我的四次错误尝试：

| 尝试 | 结果 |
|---|---|
| 14 珠 + 半径 ×1.45 | 珠链 |
| 40 珠 + 半径 ×1.25 | **珠链仍在**（半径也小了，比值仍 > 1） |
| 单中心椭球 + `size_x/y/z` 拉伸 | **段段断开**（拉伸不符合预期，别用） |
| 3 点 ×1.6 | 断节 |
| 7 点 ×1.6 | 珠链又回来 |
| **按 `段长 / (半径/3)` 自动算珠数** | ✓ 连续光滑 |

**代码**（`tools/whisper-model3.mjs` 的 `link_seg`）：
```python
rmin = max(min(r0, r1), 1e-4)
steps = max(4, int(L / (rmin / 3.0)))      # ← 判据就这一行
steps = min(steps, 90)                     # 上限，防元素数爆炸
for i in range(steps + 1):
    t = i / float(steps)
    blob(lerp(p0,p1,t), lerp(r0,r1,t) * 1.0, 2.0, squash)
```

## 三、第二条关键认知：**radius 不是表面半径**

Blender 元球的 `element.radius` 是**影响范围**，实际表面半径 ≈ `radius × 0.5~0.6`。
所以比例表里的数看着"粗"才对 —— 我第一版按"想要多粗就写多粗"填，做出来是细针，
**段与段因此融不到一起**（渲染成散球）。

## 四、比例表要**参数化**，不要逐部件手调
`CANON` 表 = 关节高度 / 横向位置 / 半径，**全部占身高 H 的比例**；
`BODIES` 只改这些常数就能出不同体型（我在用的 7 种：human/tall/stocky/child/lanky/gaunt/hulk）。
手调坐标的后果：**手臂上移就悬空、外移就脱离躯干**（我实测两版都踩）。

## 五、目录/导出侧的硬性要求（已在项目里验证）
1. **导出前必须 UV 展开**。无 UV 时 glTF 导出器为**每个面角复制顶点** → 实测 **10× 膨胀**
   （9.9k 网格顶点 → 83k GLB 顶点）。
2. **`export_yup=False`**（保持 Z-up，**与 Unity 同约定，套件同理，不要改**）。
   ⚠ 但这样导出的 GLB 在 **Blender 里再导入会躺平** —— 所以**目视检查不要走"导出→再导入"**
   （我在这条回环上错了 5 次）。**在生成进程内直接架相机渲染**（见 `tools/body-views.mjs`）。
3. **客观尺寸必须用数字核**，不要靠看图判断朝向。`tools/glb-bbox.mjs` 直接读 GLB 的
   accessor min/max：`Z 最长 → Z-up 站姿 ✓`。我先前"看图判断躺着/站着"浪费了 3 轮。
4. **顶点预算**：手机一屏 3~5 只鬼 + 关卡几何 → 单只 **≤ 8k 顶点**。
   元球细分辨率会到 25k，用 `DECIMATE(COLLAPSE)` 压（比例 = 目标/当前）。

## 六、工具（都免费、都在仓库里，谁都能用）
```
tools/whisper-model3.mjs   build --body lanky --quality low    # 生成（元球，正解）
tools/whisper-model3.mjs   all                                 # 全部体型 + 尺寸表
tools/body-views.mjs       --bodies human,lanky                # 生成进程内 4 视图渲染（目视检查）
tools/glb-bbox.mjs         <a.glb>                             # 客观包围盒（判朝向/尺寸）
tools/verify-models.mjs                                        # 从产出字节核顶点/面/材质
tools/model-sheet2.mjs                                         # 逐体型独立渲染 + 尺寸表
```
**给 build-render**：你做 `stair/lift/lobby/boiler` 套件时，若要做圆润的构件（扶手、管道、
装饰件），用**元球**比用立方体+Bevel 更省事且更好看；建筑主体仍用立方体（硬表面），
但**转角必须有 Bevel**（`width=0.012 / segments=2~3`），否则就是用户说的"矩形方体"。

## 七、我还没解决的（诚实标注）
**整体比例仍不对**：最新渲染里躯干过窄、四肢像等粗的杆 —— 因为我的半径表"上肢/下肢"给得太细，
而元球又要靠加粗才能融合。**正解方向**：把"融合所需的最小半径"与"设计想要的粗细"解耦 ——
即**先用足够粗的元球保证融合，再用整体非等比缩放**把躯干/四肢压回设计比例。
这条我尚未验证，不写成结论。
