# 鬼怪建模与机制：官方对齐说明（Lead · 权威）

> 用户 2026-10-05 明确指示的落盘。**与类型解绑**这一条已钉进长期记忆，不受上下文压缩影响。

## 一、模型 ≠ 类型（用户明令，**不要违反**）
用户原话：
> 「鬼的建模是通用的，不与鬼的类型绑定，所有鬼的建模都正常化，不要说比如随到幻影就用没腿的建模，这是错误的，
>  所有的鬼都随机几个建模（**分男女建模**），只是按机制体现不同而已」

**官方与这条一致**：恐鬼症里**同一鬼类型每次刷新会随机取不同模型**，模型与类型是解耦的
（参考 [All Phasmophobia ghost models](https://dotesports.com/phasmophobia/news/all-phasmophobia-ghost-models)）。

### 落到实现上的硬性规则
1. **`ghost.<类型>.model` 这类字段禁止存在** —— 模型由**匹配种子**随机选，不由类型决定。
2. 模型分**男 / 女**两套（本项目 `sex` 维度），每套若干体型；**每只鬼开局随机取一个**。
3. 类型差异**只体现在机制/行为**上（速度、猎杀阈值、证据、能力），**绝不体现在形体残缺**上
   （"幻影没腿""幽灵飘着"这类做法是错的）。
4. 因此**任何"按类型换模型/换部件"的代码或配置都是 bug**，门禁应能拦住。

## 二、死亡与跳脸（用户点名的机制）
用户原话：
> 「如果玩家被鬼猎杀到的话会被鬼跳脸，其余请查阅恐鬼症官方档案」

官方行为（[Death](https://phasmophobia.fandom.com/wiki/Death)）：猎杀中玩家被抓到即**死亡**，
死亡瞬间有**鬼脸扑向镜头**的动画（jumpscare）。本项目落成：
- 猎杀态下鬼与玩家距离 < `KillRadiusM` → 判定死亡；
- 死亡触发 **JumpscareView**：鬼的面部部件（头/眼）在 0.35~0.55s 内**从远处冲满屏**，
  同时相机锁定、HUD 变红、语音/音频留钩子；
- **红眼/白眼**沿用已实现的眼部自发光（用户要求"加重眼部亮处理"）。
