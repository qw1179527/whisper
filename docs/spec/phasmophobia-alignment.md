## 三、各系统的最小正确模型

### 3.1 等级（Progression）
```
经验来源：合约完成（基础） + 证据数×系数 + 存活 + 任务奖励
等级曲线：level→需要经验，用**分段**（配置表），不硬编码公式
声望：满级后可选复位，`prestige` +1，**等级归 1、装备与钱保留**（官方语义），
      历史最高等级记入 `bestLevel`
```

### 3.2 商店（Shop）
```
每件装备：{ id, tier: 1|2|3, price, weightKg, desc, effects{...} }
规则：Tier N 需先买 Tier N-1（同 id 递进）；买了即"拥有"，可装备/卸下
钱：合约结算给的钱（配置里 economy 扩展到 money 通道）；碎片仍**不可购买装备**
```

### 3.3 任务（Tasks）
```
每日 3 条 + 每周 1 条；**按日期种子确定性生成**（禁 UnityEngine.Random / DateTime.Now 参与玩法判定）
任务类型（官方确有这些类别）：收齐证据 / 拍到鬼 / 用某道具 / 存活撤离 / 在鬼房待够时间
进度由局内事件累加；结算时结算奖励
```

### 3.4 电闸（Power）
```
单总闸：开 → 全屋通电（各房间灯可单独开关）；关 → 全黑、理智掉得快
鬼互动可**关总闸**（官方行为之一）→ 玩家须回总闸重开（这是核心循环）
分区照明 = 总闸 ON 且该房间灯开关 ON
```

### 3.5 互动（Interaction）
```
玩家侧：开关灯（按房间）、开关门（已有）、电闸、拾取物（已有）
鬼侧（EMF 之外的"存在感"来源）：开关门（已有）、**开关灯**、**投掷物件**（产生声响=声纹）、
        敲击（定时声响）、**关总闸**
每次鬼互动 → 产出一条 Stimulus（本工程已有 Hearing/Stimulus 体系）→ 玩家听得到、EMF 读数变化
```

### 3.6 主界面（大厅）
```
左侧：玩家等级/经验条/声望/钱/碎片
中部：3D 走廊（已有，保留）
右侧：开始调查（单人）· 商店 · 每日任务 · 装备 · 创建/加入房间
```

## 四、验收（每项都要能真机取证）
1. 等级：结算后经验增加、升级有提示、可声望
2. 商店：能买 Tier I → 解锁 Tier II；买了能装备并影响局内数值
3. 任务：主界面能看到 3 日 + 1 周；完成条件达成后进度变动、结算发奖
4. 主界面：等级/钱/任务都在屏幕上可读
5. 电闸：单总闸开关 → 全屋灯随之；鬼能关总闸
6. 互动：鬼开关灯/投物 → 有声纹与 EMF 变化；玩家能开关灯
