## 8. 车载环境（货车 = 移动基地与安全指挥中心）
2022 年 **Truck Overhaul** 后全面重做。外观参考 **Iveco Eurocargo 75E18**；
车牌 **7GHD666**（GHD = 虚构公司 Ghost Huntin' Distribution，666 彩蛋）。内部前部指挥区 + 后部装备区。

核心功能区：

  左击切换摄像头，左击键盘切换夜视（探测灵球与 D.O.T.S. 痕迹）
- **信息与任务面板**（乘客侧前部）：显示本合约目标与鬼魂信息；旁边是**地点地图**，

- **装备墙**（后部）：携带与初始装备挂在墙架上；可取用，也可按"次要使用键"放回

## 10. 机制（用户给的完整补充）

### 理智
- 个人理智 + **团队平均理智**（后者决定事件与猎杀）；货车屏幕理智有 ±2% 随机波动，
  平均理智波动 ±2%×人数；**噩梦/疯狂难度不显示理智屏**
- 被动消耗取决于房间主灯是否开启；黑暗中小图约 0.12%/分、大图约 0.05%/分；
  单人减半；**血月天气翻倍**；手持火光（蜡烛/打火机）可减慢消耗，火光等级越高越好；
  **站在调查区域外（货车内）完全不掉**
- 理智为 0 **不会死**，只是猎杀概率最高

### 猎杀
- 部署期：业余 5 分钟安全期、中级 2 分钟、专家/噩梦/疯狂无；**用任何诅咒道具立即结束部署期**
- 阈值：多数鬼在**平均理智 ≤50%** 才可能猎杀；恶魔 70%、暗影 35%、雾影 40%；
  **女妖只算锁定目标的理智**，不受团队平均影响
- 冷却：猎杀结束 **25 秒**（恶魔 20 秒）；十字架抵挡后同样进入冷却
- 猎杀中电子设备受干扰；**开启的设备 7.5m 内吸引鬼魂**（妖怪 2.5m）；全局语音切断
- **诅咒猎杀**：由误用诅咒道具触发，**无视理智与冷却**，比普通猎杀**长 20 秒**；
  **只有三级十字架能挡**，一二级无效

### 证据与互动
- Chronicle 后证据分**照片/视频/音频**三类；首次捕获标"**唯一**"给额外奖励；重复捕获奖励降低；
  **完美调查需要日记中全部为独特媒体**
- 鬼可**隔墙互动**，但一般不跨楼层；每次互动产生 EMF 读数**持续 20 秒**；
  有 EMF 5 级证据的鬼每次互动 **25%** 概率出五级读数
- 互动频率影响因素：难度越低 / 周围有圣木 / 说出鬼的名字 / 理智越低 / 使用诅咒道具 → **提高**

### 鬼魂事件
需先**被激活**（首次开启出口门后）才会互动/事件/猎杀；未激活仍可能留下部分证据。
喷烟类事件直接扣目击者 **10% 理智**；平均理智每低 1%，事件成功率 **+2%**。

### 声音
鬼**监听玩家麦克风音量**；在鬼附近大声说话会吸引它；**说出鬼的名字**有概率提高互动频率（10 秒冷却）。
官方语音已从 Photon Voice 迁到 **Vivox**。

### 难度
5 档默认 + 完全自定义；可调鬼/玩家移速、初始理智、理智下降速度、跑步耐力、
手电是否可用、死亡是否掉装备等，设定可保存。**动态难度**：小队平均等级越高，鬼攻击间隔越短，
可能解锁"设备干扰"。<br>**单人模式**：鬼攻击频率 **−30%**，理智下降相应减缓。

### 移动与速度
- 玩家：常规行走速度已提升至旧版冲刺速度；**冲刺持续 3 秒、冷却 5 秒**
- 鬼基础速度 **1.6–1.7 m/s**；**视线加速（LOS）**是通用机制；
  多数鬼 LOS 上限 **2.5 m/s**；亡魂看见目标 3 m/s、失去目标约 1 m/s；
  雾影远处极快近身极慢（约 0.4 m/s）；魔洛伊 0 理智 + 满视加可达 **3.7 m/s**（最快）

### 联机
跨平台（PC/PS5/Xbox）联机但**不跨平台进度同步**；**房间制、无专属服务器**，由房主网络决定质量。

### N1. 后处理合成 pass 跑起来就黑屏（**默认已旁路**）
- **现象**：`PostFx.OnRenderImage` 里只要真的执行合成 pass（`Graphics.Blit(src, dst, _mat, 3)`），
  画面整片黑；走 `Graphics.Blit(src, dst)` 直通则完全正常。
- **已排除**（每一条都有真机或构建日志证据）：
  1. 着色器编译 —— d3d11 / gles3 / vulkan 三后端 0 错误（0.1.46 修掉嵌套三元后）；
  2. 曝光 —— 眼部适应读回恒为 0（`raw=0.00`），已改为"读回无效则回中性"，HUD 实测 `曝光 1.00`，仍黑；
  3. SSAO / SSGI / 体积光 —— 已全部默认关，仍黑；
  4. 辉光判据不一致（`t.Bloom` vs `BloomIntensity`）—— 已统一，仍黑；
  5. 组件被 `enabled=false` 导致深度纹理失效 —— 已改为 `Bypass` 标志，仍黑。
- **当前处置**：`PostFx.BypassByDefault = true`（默认旁路），并在 EditMode 里加了三条
  **"SSAO/SSGI/眼部适应必须默认关"** 的断言 —— 谁改回 true 就会红，提醒先修根因。
- **下一步（独立课题）**：不要再用"出 APK 请用户看黑不黑"的方式试错。
  应改用**离屏取证**：在编辑器里对一个固定相机渲染一帧、把合成 pass 的中间缓冲
  （亮部/模糊/最终）逐个导出 PNG 对比，定位是哪一级变黑。
  另一条更稳的路线：改用 `CommandBuffer`（`CameraEvent.AfterForwardAlpha`）注入，
  而不是 `OnRenderImage` —— 后者在移动端与深度纹理的配合本身就有已知坑。
